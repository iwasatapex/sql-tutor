SQL TUTOR - OLLAMA SETUP GUIDE
================================

This guide explains how to run SQL Tutor with your own local Ollama model.
SQL Tutor can also run without Ollama by using its default mock provider.

1. REQUIREMENTS
---------------

You need:

- Python 3.12 or newer
- Git
- Ollama (only required for local LLM features)
- A downloaded Ollama model

From the SQL Tutor project directory:

    cd ~/Projects/sql-tutor

Create and activate a Python environment if you do not already have one:

    python -m venv .venv
    source .venv/bin/activate

Install the project:

    python -m pip install -e ".[dev]"

If you use Conda instead, activate your existing environment and run:

    python -m pip install -e ".[dev]"

2. INSTALL AND CHECK OLLAMA
---------------------------

Install Ollama using the official instructions for your operating system:

    https://ollama.com/download

Check that Ollama is available:

    ollama --version

Check whether the Ollama server is responding:

    ollama list

If the server is not running on Linux, start it in another terminal:

    ollama serve

Do not start a second Ollama server if one is already running as a system service.

3. DOWNLOAD A MODEL
--------------------

Choose a model that your computer can run comfortably. Examples:

    ollama pull granite4.1:3b-q6_K
    ollama pull batiai/gemma4-e4b:q4
    ollama pull ornith-1.5-9b-iq4-xs:latest

List installed models:

    ollama list

Test a model directly:

    ollama run <your-model-name>

Replace <your-model-name> with the exact name shown by `ollama list`.

The model name in SQL_TUTOR_LLM_MODEL must match the Ollama model name exactly.

4. CONFIGURE SQL TUTOR - OLLAMA
--------------------------------

SQL Tutor reads its LLM configuration from environment variables.

Required variables:

    SQL_TUTOR_LLM_PROVIDER=ollama
    SQL_TUTOR_LLM_MODEL=<your-model-name>

Optional variables:

    SQL_TUTOR_LLM_BASE_URL=http://localhost:11434
    SQL_TUTOR_LLM_TIMEOUT=120

Linux/macOS - Bash or Zsh:

    export SQL_TUTOR_LLM_PROVIDER=ollama
    export SQL_TUTOR_LLM_MODEL=<your-model-name>
    export SQL_TUTOR_LLM_BASE_URL=http://localhost:11434
    export SQL_TUTOR_LLM_TIMEOUT=120

Linux - Fish shell:

    set -gx SQL_TUTOR_LLM_PROVIDER ollama
    set -gx SQL_TUTOR_LLM_MODEL <your-model-name>
    set -gx SQL_TUTOR_LLM_BASE_URL http://localhost:11434
    set -gx SQL_TUTOR_LLM_TIMEOUT 120

Example for a Granite model in Fish:

    set -gx SQL_TUTOR_LLM_PROVIDER ollama
    set -gx SQL_TUTOR_LLM_MODEL granite4.1:3b-q6_K
    set -gx SQL_TUTOR_LLM_BASE_URL http://localhost:11434
    set -gx SQL_TUTOR_LLM_TIMEOUT 120

These variables apply only to the current terminal session. To make them
persistent in Fish, add the `set -gx` commands to:

    ~/.config/fish/config.fish

5. START SQL TUTOR
------------------

Start the command-line tutor:

    python -m sql_tutor.cli practice

Start the browser UI:

    python -m sql_tutor.cli web --open

Or start the browser UI without opening a browser automatically:

    python -m sql_tutor.cli web

Then open:

    http://127.0.0.1:8765

The browser UI and command-line tutor use the same progress database and
optional LLM configuration.

6. TEST THE LLM CONFIGURATION
-----------------------------

Generate and validate an exercise through Ollama:

    python -m sql_tutor.cli generate \
      --concept "GROUP BY" \
      --difficulty intermediate \
      --save

The generated exercise is validated and executed against a scratch SQLite
database before it is saved. Generation can take time depending on the model,
CPU, GPU, context length, and Ollama configuration.

7. RUN WITHOUT OLLAMA
---------------------

Ollama is optional. If no provider is configured, SQL Tutor uses the mock
provider by default:

    set -e SQL_TUTOR_LLM_PROVIDER
    set -e SQL_TUTOR_LLM_MODEL
    python -m sql_tutor.cli web --open

For Bash or Zsh, use:

    unset SQL_TUTOR_LLM_PROVIDER SQL_TUTOR_LLM_MODEL
    python -m sql_tutor.cli web --open

The tutor's deterministic hints and SQL exercises still work without a real
LLM. Real model-generated hints require the Ollama provider to be configured.

8. USE A DIFFERENT OLLAMA SERVER
--------------------------------

If Ollama is running on another host or port, change the base URL. For example:

    set -gx SQL_TUTOR_LLM_BASE_URL http://192.168.1.50:11434

Make sure the server is reachable from the machine running SQL Tutor and that
its firewall allows the connection. Do not expose an Ollama server publicly
without understanding the security implications.

9. PROGRESS AND DATA LOCATIONS
------------------------------

By default, progress is stored at:

    ~/.local/share/sql-tutor/progress.db

You can use a different progress database:

    python -m sql_tutor.cli --db /path/to/progress.db web --open

You can use a different data directory:

    python -m sql_tutor.cli --data-dir /path/to/data web --open

10. TROUBLESHOOTING
-------------------

Error: "Could not reach http://localhost:11434"

- Confirm Ollama is running.
- Run `ollama list`.
- Check SQL_TUTOR_LLM_BASE_URL.
- Check whether a firewall or network rule blocks the connection.

Error: model not found

- Run `ollama list`.
- Run `ollama pull <exact-model-name>`.
- Set SQL_TUTOR_LLM_MODEL to the exact installed name.

Error: SQL_TUTOR_LLM_MODEL must be set

- Set SQL_TUTOR_LLM_PROVIDER=ollama.
- Set SQL_TUTOR_LLM_MODEL to an installed model name.

The model is too slow or uses too much memory

- Try a smaller model or a smaller quantization.
- Avoid running multiple large models simultaneously.
- Check GPU and RAM usage.
- Increase SQL_TUTOR_LLM_TIMEOUT if generation regularly exceeds 120 seconds.

The browser UI does not start

- Confirm the command is run from the SQL Tutor project directory.
- Check that the Python environment is activated.
- Run `python -m pytest -q` to validate the installation.
- Try another port, for example:

    python -m sql_tutor.cli web --port 8877

11. SECURITY NOTES
------------------

- SQL Tutor restricts learner queries to a single SELECT or WITH statement.
- Learner SQL runs with SQLite query-only protections, a timeout, and a row cap.
- Keep local model servers on trusted networks.
- Never share API keys or private server URLs in public repositories.

12. USEFUL COMMANDS
-------------------

    python -m sql_tutor.cli --help
    python -m sql_tutor.cli practice
    python -m sql_tutor.cli web --open
    python -m sql_tutor.cli progress
    python -m sql_tutor.cli list --concept join
    python -m pytest -q
